# STE100-Inspired English Basics

Use this profile when a team wants technical English that is easy to scan,
translate, and follow under pressure. This is a practical subset inspired by
ASD-STE100. It does not claim compliance.

## Core Rules

- Keep procedures short. Aim for one action per sentence.
- Keep explanations short. Split long chains of clauses.
- Put the condition before the action.
- Prefer active voice.
- Use simple verb forms.
- Keep one term for one concept across the document.
- Delete filler such as `simply`, `seamlessly`, `robust`, and `it is important to note`.
- State concrete commands, files, values, and outcomes.

## Good And Bad Pairs

### Pair: Filler opening

Bad: To seamlessly configure the client, you should first make sure that the relevant credentials are properly set up.

Good: Before you configure the client, set the required credentials.

### Pair: Condition after command

Bad: Restart the service if the port is already in use.

Good: If the port is already in use, restart the service.

### Pair: Two actions in one sentence

Bad: Open `config.yml` and update the endpoint and restart the service.

Good: Open `config.yml`. Update the endpoint. Then restart the service.

### Pair: Vague claim

Bad: The retry logic provides robust handling for temporary failures.

Good: The client retries temporary failures three times.

### Pair: Noun-heavy procedure

Bad: Perform validation of the token before execution of the command.

Good: Validate the token before you run the command.
